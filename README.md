# CH Darts Training Analyzer β (ベータ版)

> **これは検証用のベータ版リポジトリです。** 本番版とは別のリポジトリ・別のURL・別のブラウザ保存領域で動作します。
>
> | | 本番版 | ベータ版(このリポジトリ) |
> |---|---|---|
> | URL | `https://chihirohashimotoac-coder.github.io/chtrainer/` | `https://chihirohashimotoac-coder.github.io/chtrainer-beta/` |
> | バージョン | 2.6.0 | 2.7.0-beta.2 |
> | IndexedDB | `darts-training-analyzer` | `darts-training-analyzer-beta` |
> | SWキャッシュ | `dta-v<version>` | `dta-beta-v<version>` |
> | localStorage(テーマ) | `chtrainer-theme` | `chtrainer-beta-theme` |
>
> 2つは同じオリジン(`github.io`)配下のためパスだけでは保存領域が分離されません。上記のとおり識別子をすべてベータ専用にしており、**同じブラウザで両方を同時に使ってもデータは混ざりません。また自動同期もされません。**
> 本番版の記録をベータ版で使う場合は、本番版でJSONバックアップを書き出し、ベータ版の「バックアップ / 復元」から読み込んでください(自動コピー・自動移行は行いません)。
> 分離はテスト(`src/beta/betaIsolation.test.ts`)で機械的に検証しています。

ダーツの投擲を記録し、AI分析用の依頼文(Markdown)を生成するトレーニング支援PWAです。

- スマートフォン最優先のUI(PCブラウザでも利用可能)
- 1セット3投で指定ターゲットへ投げ、着弾位置を記録
- 投擲データは**端末内のIndexedDBにのみ保存**(サーバー・外部DBなし)
- 基本統計(命中率・誤差・投順別・ターゲット別・方向別・前半後半)をアプリ側で算出
- 全投擲データと統計を含む**AI分析依頼Markdown**を生成し、コピーまたは`.md`保存
- **[ベータ版] ローカルコーチ事前分析(ルールベース)** を依頼文へ追加(下記参照)
- CSV出力(UTF-8 BOM付き)・JSONバックアップ/復元
- オフライン動作(Service Worker)・ホーム画面追加対応

> **本アプリはAI APIを内蔵していません。** APIキーの入力機能もありません。
> 生成されたMarkdownを、ご自身が利用するChatGPT・Claude・Gemini等へ貼り付けて分析を依頼する設計です。

> **免責**: 本アプリはDARTSLIVE、PHOENIX等の既存ダーツサービスとは一切関係のない、非公式の個人用トレーニングツールです。既存サービスの名称・ロゴ・画像・デザインは使用していません。疲労度・痛み等の自己評価は医学的診断ではありません。

## ローカルコーチ事前分析(ルールベース) — ベータ版の新機能

AI分析依頼Markdownへ、アプリ内で決定論的に算出した事前分析を追加します。

- **完全ローカル・ルールベース。生成AIや機械学習モデルは搭載していません。** 外部API・APIキー・追加費用は不要で、オフラインでも動作し、同じ入力からは常に同じ結果を返します。
- 実装: `src/domain/localCoach/`(分析) と `src/export/localCoachMarkdown.ts`(整形)。分析関数は純粋関数で、内部からIndexedDBを読みません。
- 分析結果は保存せず、Markdown生成時に毎回再計算します(ルール更新後は過去セッションも最新ロジックで再分析されます)。エンジン版数は依頼文へ `local-coach-v2.0` として出力します。

### 分析する項目

| 分類 | 内容 |
|---|---|
| 投順別 | 横方向・縦方向のばらつき、命中率 |
| 時間変化 | 前半・後半の命中率、平均誤差距離、アウトボード率、投擲間隔(中央値) |
| 方向 | 「偏り」(平均が片側へ寄る)と「再現性不足」(散らばりが大きい)の区別、簡易入力時の外れ方向の頻度 |
| グルーピング | 前半・後半の径、セット内の投順間距離(1→2投目 / 2→3投目)、過去との比較 |
| 条件依存 | ターゲット切替直後、命中後・ミス後の次投、反対方向への過剰修正 |
| ターゲット別 | 十分な出題数があるターゲット間の命中率差(弱点・強み) |
| モード別 | クリケット(ノーマーク率・ナンバー切替直後の平均マーク) / 01(Bull・トリプル・ダブル間の命中率差) |
| 長期 | 比較可能な4セッション以上での命中率・平均誤差距離の連続した推移 |

### 推定の不確実性の扱い

閾値を超えただけでは断定しません。比率にはWilsonスコア区間、2群の比率差にはNewcombe法、平均差にはWelch流の標準誤差、ばらつきの比には対数変換による近似区間を用い、**差の95%区間が0をまたぐ場合(標本が少なく向きが反転しうる場合)は確からしさを1段階下げます**。これにより「10投での15ポイント差」と「100投での15ポイント差」を同格に扱いません。

区間は推定のぶれ幅の目安としてのみ示し、複数の指標を同時に見ているため**有意性の判定には使いません**(依頼文にもその旨を明記します)。

課題の並び順はルールの記述順ではなく、**効果量 × 確からしさの重み**で決まります。同じ主題を複数の独立した指標が裏付けている場合(例: 3投目のばらつき増大と3投目の命中率低下)にのみ確からしさ「高」に到達します。

### 分析不能とする条件

該当サンプルが10投未満、比較可能な過去セッションがない、詳細座標が不足、有効な3投セットがない、ターゲット切替サンプルが0件、など。データが足りない場合は架空の分析を生成せず、理由を明示します。閾値は `src/domain/localCoach/config.ts` に集約しています。

### 断定しないこと

身体動作(グリップ・肘・肩・手首・リリース)、医学的・心理的・性格的な状態は判定しません。着弾データから観測できる「状態」だけを記述し、原因仮説は外部の生成AIに委ねます。依頼文には、ローカル分析を無条件に採用せず独立検証するよう外部AIへ指示する節も含めます。

## データ保存方式

- すべてのデータは端末内の IndexedDB (`darts-training-analyzer`) に保存されます
- ストア: `settings` / `players` / `equipmentProfiles` / `trainingPlans` / `sessions` / `throwSets` / `throws` / `sessionStatistics` / `appMetadata`
- 投擲はセット確定ごとに即時保存され、ページ再読み込み後も進行中セッションを再開できます
- 全レコードがスキーマバージョン(`schemaVersion`)を持ち、将来のデータ移行に備えています
- **ブラウザデータの削除でデータが消えます。** 定期的なJSONバックアップを推奨します

## バックアップ方法

- **JSONバックアップ(正式なバックアップ形式)**: 設定 → バックアップ・復元 → 「JSONバックアップを保存」。
  復元時は構造検証 → バージョン確認 → 件数表示 → 追加/置き換え選択 → 確認 → 単一トランザクションでインポート(失敗時は既存データを維持)
- **CSV出力**: セッション単位。人間による確認・表計算・AIへの添付・二次バックアップ用(完全復元はJSONのみ)

CSVの`assessment_{before|middle|after}_uninterrupted_throw_rate_percent`は開始前・中間・終了時の「止まらず投げられた割合」(0〜100%)、`assessment_{before|middle|after}_release_stop_timing`は同じ各時点の停止タイミングです。旧セッションの未記録値は空欄です。

## データモデル概要

主要な型は `src/types/models.ts` を参照してください。

- `PlayerProfile` — 表示名・利き腕・利き目・スタンス・標準ボード・フライト色(投順識別)・入力方式など
- `EquipmentProfile` — バレル/シャフト/フライト/チップのセッティング情報
- `TrainingSession` — モード・セット数・出題ターゲット計画・自己評価・環境・進行状態
- `ThrowSet` / `ThrowRecord` — セットと投擲。着弾(`landing`)と派生データ(`derived`: 誤差・ズレ方向・命中など)
- `SessionStatistics` — アプリ算出の基本統計

### 座標系

- ボード中心が原点、右が +X、上が +Y
- **外側ダブル外周の半径 = 1.0** の正規化座標
- 角度は20方向(真上)が0度、時計回りが正、0以上360未満
- 簡易入力の座標はエリア代表点(幾何学的中心)による**概算値**で、
  `positionPrecision = "segment_approximation"` として区別されます

## ボードプロファイル(初期寸法と前提)

寸法は `src/config/boardProfiles.ts` で一元管理しています(コンポーネントに直書きしていません)。

| 部位 | 実寸半径(mm) | 正規化 |
|---|---:|---:|

## 外部AIへデータを渡す際の注意

- 生成Markdownにはセッション概要・環境メモ・自己評価・全投擲データが含まれます。
  外部AIサービスへ貼り付ける前に、含めたくない情報(練習場所など)がないか確認してください
- 各AIサービスの利用規約・データ取り扱いポリシーに従ってください
- 分析結果は運動学習の参考情報です。医学的判断には使用しないでください

## v1.18.0: 分析データの信頼性

- セッション開始時にプレイヤー、目的、入力方式、ダーツ色、ボード、セッティングを `SessionContextSnapshot` として保存します。以後プロフィールや用品を編集しても過去の分析依頼は変わりません。v1.17以前のセッションは現在プロフィールへ安全にフォールバックし、Markdownに警告を表示します。
- `completedThrows` は入力完了数、`scorableThrows` は完全命中を判定できる投擲数です。`scorableExactHitRate = exactHits / scorableThrows` とし、スキル診断R1の `grouping_only` は分母から除外します。`errorSampleCount` は誤差距離を算出できた別のサンプル数です。
- R1には型付きのラウンドメタデータを保存し、詳細座標入力を必須にしました。簡易入力の座標はセグメント代表点にすぎないため、精密な散布・グルーピング距離には使用せず「分析不能」とします。
- AI依頼は共通ルール、モード別、目的別の短いブロックで構成し、根拠のない100点採点を禁止しました。事実、傾向、仮説、分析不能を分離し、復調記録は医学的・心理的診断ではないことを明記します。
- Markdown、投擲CSV、スナップショットを含む `metadata.json` を一括したZIPを保存できます。JSZip 3.x（MIT / GPL-3.0-or-laterのデュアルライセンス）を利用します。
- バックアップ形式はv2です。v1を引き続き読み込め、新フィールド欠落時は安全な旧データとして扱います。IndexedDBはv2へ非破壊更新され、既存ストアやレコードを書き換えません。インポート前の構造検証に失敗した場合、既存データは変更されません。

### 移行時の注意

古いセッションに開始時点の情報を後から正確に復元することはできません。そのため値を推測して埋めず、現在値へのフォールバック警告を残します。新しい統計はセッション詳細を開いて再計算された時点で保存されます。
